# AGENTS.md

Event Horizon is a Wayland desktop shell written in Zig 0.16 (version 0.1.0).
It runs as a layer-shell client next to a compositor (Hyprland, Niri, Sway,
Mango, Labwc) and provides dock, taskbar, desktop, overview, settings,
notifications, lock screen, wallpaper, clipboard history and audio control.
Linux and Wayland only. The old C++/Meson tree is gone; the Zig build is the
only build.

## Rules that prevent most mistakes

1. Zig 0.16 differs from what you remember. This code uses the new `std.Io`
   API: `pub fn main(init: std.process.Init)`, `init.gpa`, `init.io`,
   `std.Io.File`, `std.Io.Dir`, and writers that take an `io` argument.
   Never write a `std` call from memory. First grep this repo for an existing
   use of the same API and copy its shape. If there is none, look up the real
   signature in the installed stdlib (`zig env` prints the lib directory; the
   source is in `<lib_dir>/std`). On a compile error about an unknown
   declaration, look it up. Do not guess variants.
2. Never run `./build.sh` without `--no-install`. By default it installs to
   `/usr` through `pkexec`/`sudo`. Use `zig build` instead.
3. Never use `@cImport`. C headers are translated in `build.zig` and imported
   as modules: `c_stdlib`, `c_pthread`, `c_cairo`, `c_xkbcommon`, `c_wayland`,
   `c_polkit`, `c_spawn`. A new C header means a change to `build.zig`.
4. `CHANGELOG.md` describes the old C++ tree. Its paths (`.cpp` files,
   `horizon-stage`, `horizon-panel`) do not exist here. Do not use it as a map
   of the code. Trust the file tree and `README.md`.
5. `.github/workflows/linux-packages.yml` is stale (Meson, C++) and fails
   because there is no `meson.build`. Ignore it. Do not add Meson files.
6. Do not hand-edit vendored or generated files: `third_party/stb/`,
   `protocols/*.xml`, `assets/fonts/`, and the Lucide SVGs plus lookup table
   in `src/ux/shared/` and `src/ux/settings2/` (generated by
   `scripts/gen_lucide_icons.py`). `src/color/mcu/` is a port of
   material-color-utilities; keep it numerically faithful.
7. Several files are 1000-3100+ lines (`src/ux/audio_center/window.zig`,
   `src/ux/settings2/sound_tab.zig`, `src/ux/settings/*`, much of `src/m3/`).
   Never read one of these in full. Grep for the symbol or section first, then
   read only that line range. A full read burns most of a local model's
   context budget in one call and triggers compaction.
8. Do not edit, import, or copy the pattern of scratch files:
   `src/tmp_*.zig`, `src/scratch_bar.zig`, `src/zz_monitors_smoke_test.zig`,
   `New Document.log` (a CI log), `src/.zig-cache/`, `scripts/__pycache__/`,
   `assets/.state/`.

## Commands

```bash
zig build                                  # all binaries, Debug (slow, large)
zig build -Doptimize=ReleaseFast           # use this to actually run the shell
zig build -Doptimize=ReleaseFast -Dcpu=x86_64_v3   # portable (v2, v3, v4)
zig build dock                             # one binary; steps below
zig build test                             # unit tests, root src/tests.zig
zig build test -Dtest-root=src/security_tests.zig  # image security tests
python3 scripts/test_image_security.py     # needs a C compiler with ASan/UBSan
python3 scripts/test_install_security.py   # checks build.sh install branches
./build.sh --no-install --jobs 8           # supported build path, no /usr writes
```

Per-binary steps: `horizon`, `ipc`, `wallpaper`, `dock`, `taskbar`, `desktop`,
`desktop-widgets`, `settings2` (produces `horizon-settings`), `overview`,
`notifications`, `polkit-agent`, `clipboard`, `clipstack`, `clipstack-pick`,
`audio-center`, plus `install-icons --prefix ~/.local/share`.

`zig build` runs `pkg-config` and `wayland-scanner` at configure time. A
missing `-devel` package fails the build at that point.

Run and debug:
- Run from `zig-out/bin/`. The `horizon` supervisor starts its components from
  its own directory, not from `PATH`.
- Set `EH_ZIG_ISOLATED=1` when testing so config goes to
  `~/.config/Event-Horizon-zig` instead of the live config. Never delete or
  rewrite `~/.config/Event-Horizon*`.
- Logs: `~/EH-logs/<tag>.log` (rotates at 64 MiB). IPC check: `eh-ipc status`.
- The GUI needs a live Wayland session and cannot be checked headless. If you
  cannot run it, say what you did not verify.

## Architecture

- `horizon` (`src/main.zig`, `src/bootstrap/`) is the supervisor. It spawns and
  restarts component processes and serves the IPC socket
  `$XDG_RUNTIME_DIR/event-horizon-ipc.sock` (override: `EH_IPC_SOCKET`).
  Spawn gating is in `src/bootstrap/spawn.zig`.
- Every component is its own process with its own Wayland connection. The list
  lives in the `binaries` array in `build.zig`.
- `src/eh.zig` is the shared `eh` module. Roots under `src/bin/*.zig` reach the
  rest of `src/` only through `@import("eh")`; their module root is `src/bin`,
  so `../` imports fail. A new shared module must be re-exported from `eh.zig`.
  A few roots sit directly in `src/` and import by path: `overview_bin.zig`,
  `notifications_bin.zig`, `polkit_agent_bin.zig`, `eh_ipc.zig`, `main.zig`.
- `src/bin/panel.zig` is not built (README: `horizon-panel` is not part of the
  build). `src/bin/settings.zig` is the original settings root and is also not
  in the `binaries` table.
- Directories: `backends/` (Hyprland, Niri, Sway, Mango), `config/` (TOML
  parser, layered loader, schema, watcher), `desktop_shell/` (dock, taskbar,
  desktop, overview, lockscreen, OSD, widgets), `services/` (D-Bus clients,
  notifications, tray, MPRIS, polkit, UPower, network), `wl/` (Wayland
  connection, layer surfaces, input, capture), `wallpaper/`, `color/` (Material
  You engine), `clipstack/`, `m3/` (Material 3 tokens and widgets), `text/`,
  `ux/` (settings, Audio Center, disk tools).
- The active settings app is `src/bin/settings2.zig` with `src/ux/settings2/`.
  `src/ux/settings/` is the original and is still imported by other code.
  Check which one a change belongs to before editing.
- Rendering is CPU: Cairo and Pango into `wl_shm` buffers, librsvg for icons,
  libwebp for thumbnails. Do not introduce GTK, Qt or GPU toolkits.
- Config is TOML under `~/.config/Event-Horizon/`, merged in order: `*.toml`,
  then `settings.toml`, then `<component>/<component>.toml`. Files are watched
  and reload live. Schema: `src/config/schema*.zig`. Components:
  `kComponents` in `src/config.zig`.

## Conventions

- 4-space indent, `snake_case.zig` files, `camelCase` functions, `PascalCase`
  types, `kName` for constants, `g_name` for module-level mutable state.
- Start a file with a `//!` module comment explaining what and why. Use `///`
  on public declarations. Comments explain why, not what. Match this.
- Log with `eh.logz` (`logz.log`, `logz.err`). Prefer it to `std.debug.print`.
- Pass `std.mem.Allocator` and `io: std.Io` explicitly. Do not add global
  allocators.
- Optional services (UPower, BlueZ, PipeWire) may be absent. Hide the feature
  or degrade; never crash.
- Image limits are security controls: cover art 4 megapixels, wallpapers 16
  megapixels, 128 MiB per decoder allocation, 256 MiB total. Do not loosen them.
- Run `zig fmt` on files you edit. If it would change lines you did not touch,
  do not reformat the whole file.
- Smallest change that works. Edit existing modules before creating new ones.

## Checklists

New test: add `test "..."` in the file, then add `_ = @import("path.zig");` to
`src/tests.zig`. Many existing files with `test` blocks are not listed there,
so do not assume a test runs because it exists. Make it fail once to confirm.

New component binary: add to `binaries` in `build.zig`, to `INSTALL_BINARIES`
in `build.sh`, to the Binaries table in `README.md`, and to spawn gating in
`src/bootstrap/spawn.zig` if it is optional.

New Wayland protocol: add to the `protocols` array in `build.zig` and to the
`c_wayland` include list there.

New setting: add to the schema in `src/config/schema*.zig` and to the settings
UI in `src/ux/settings2/`.

New icon: add the SVG to `src/resources/icons/`. It installs as
`event-horizon-<stem>.svg` through `zig build install-icons`.

Version bump: `src/version.zig` and `build.zig.zon`.

## Done means

`zig build` succeeds, `zig build test` passes if you touched tested logic, and
your report lists what you ran and what you could not verify.
